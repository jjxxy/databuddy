# Atlas DataBuddy

**用对话完成资料整理、数据分析和办公交付的个人 AI 工作空间。**

Atlas DataBuddy 面向财经、业务分析和日常办公场景。你可以把文件、数据和工作目标交给 Agent，让它读取资料、编写处理逻辑、调用工具、检查结果，并生成可下载、可继续修改的成果。

项目把资料、对话、处理代码、运行记录和成果放在同一个工作空间里。一次工作留下的规则与文件，可以在下一次继续使用。

## 你可以用它做什么

| 场景 | 可以交给 Agent 的工作 |
| --- | --- |
| 整理资料 | 阅读多份表格和文档，整理内容、提取信息、标注需要核对的来源 |
| 分析数据 | 清洗明细、关联数据、按业务口径汇总、比较差异并生成图表 |
| 生成办公成果 | 编写分析报告，生成 Excel、Word、PPT 等文件，下载后继续使用 |
| 建立数据应用 | 将处理结果保存为可搜索、筛选、分页查看的表格与汇总应用 |
| 持续跟进工作 | 复用处理规则，刷新数据、安排定时任务，接着修改已有成果 |

例如，你可以在对话里提出：

> 把这几份销售明细按客户汇总，只统计已付款订单，扣除退款，列出异常记录。

> 根据本月实际与预算做差异分析，生成 Excel 和汇报文稿；缺少依据的结论标出来。

> 沿用上个月的处理规则，换成本月资料，先给我预览，核对后再发布。

具体能完成的任务取决于所用模型、已提供的资料和已配置的工具。数据库、公司资料和业务系统需要先建立获准连接。

## 日常怎么使用

1. **打开项目**：按工作主题组织资料，每个项目可以保留多段对话。
2. **提供资料**：一次上传多份文件，或使用已接入的数据库、API 和业务系统。
3. **说明目标**：告诉 Agent 需要什么结果、采用什么口径，再通过对话补充和调整。
4. **查看成果**：在“成果”中查看数据、报告、图片和文件，下载或带回对话继续修改。预览方式随格式而定，Word/PPT 提供内容视图，HTML/代码提供文本视图。
5. **核对并复用**：需要正式发布的结果先确认；后续可以重跑、调整规则或安排更新。

页面提供两种模式：

- **聊天模式**：讨论问题、解释资料、查询已有内容。
- **工作模式**：让 Agent 创建或修改文件、构建处理任务、运行工具并交付成果。

服务运行时，关闭浏览器不会停止后台任务。再次打开后可以查看原来的对话、进度和成果；任务遇到中断时，可根据保存状态继续处理。

## 核心能力

- **项目与版本**：项目内共享资料和上下文；工作文件变更自动记录本地 Git 版本，支持查看历史和回退。应用内项目版本默认不会自动推送到 GitHub/GitLab。
- **数据接入与加工**：支持 CSV、Excel、JSON、文档，以及只读数据库和 REST API；保留来源版本、处理代码与运行记录。
- **代码执行**：部署独立隔离执行服务后，Agent 可运行 Python、Node 和 Bash，查看日志、保存文件检查点、取消任务并继续修改成果。
- **研究与检查**：启用公开研究后可搜索网页、阅读原文并引用来源；支持将办公文件和网页渲染为页图，配置视觉模型后可检查实际图像与版式。
- **成果交付**：统一管理报告、表格、图表、办公文件和代码，支持预览、下载及再次使用。
- **长期使用**：支持定时更新、可编辑记忆、上下文压缩，以及本地文件夹工作模式。
- **能力扩展与协作**：可安装 Skills、连接获准的 MCP 工具，调用内置专长 Agent 或接入其他 Agent。模型目录由管理员提供，用户在前台选择模型名称。

底层由大模型理解目标、Agent 编排工具与任务、执行环境运行代码，持久存储保存项目状态与成果。默认快速启动沿用 OpenCode Agent；通用代码执行需要额外部署下文的工作模式服务。

## 快速开始

准备好 **Docker Desktop**（Windows 使用 Linux 容器）或 **Docker Engine + Compose v2**，以及支持工具调用的 OpenAI 兼容模型接口。默认启动方式无需在本机安装 Python 或独立数据库。

**1. 获取源码**

```bash
git clone https://github.com/jjxxy/databuddy.git
cd databuddy
```

**2. 在项目根目录创建 `llm.json`，填写模型连接**

```json
{
  "default_model_id": "default",
  "models": [
    {
      "id": "default",
      "name": "工作助手",
      "base_url": "https://your-llm.example.com/v1",
      "model": "YOUR_MODEL",
      "api_key": "YOUR_API_KEY",
      "share_data": true
    }
  ]
}
```

替换 `base_url`、`model` 和 `api_key`。`share_data: true` 允许任务需要的业务内容发送给所选模型服务，请先确认资料授权；不要提交或分享填好的配置文件。首次构建和模型访问需要网络，模型调用可能收费。

**3. 启动并打开工作空间**

- Windows：双击 `start.cmd`。
- Linux / macOS：在项目目录执行 `bash start.sh`。

就绪后，终端会显示访问地址和工作空间口令，默认地址为 [http://localhost:8000](http://localhost:8000)。

**需要运行 Agent 编写的 Python / Node / Bash 代码时，还需单独部署隔离执行服务。** 它不随默认启动自动创建，配置步骤见 [云端工作模式](WORK-MODE.md)。模型配置、停止服务、升级与故障排查见 [快速启动指南](QUICKSTART.md)。

## 使用范围

- 默认实例适合个人或共同授权的团队空间，成员共享项目资料；需要独立账号与数据隔离时，按 [独立部署指南](deploy/isolated/README.md) 配置。
- 图片与扫描 PDF 可提取 OCR 文字候选，复杂表格、金额、公式及业务口径仍需对照原件核查。生成文件、执行成功或通过结构检查，都不能代替财经复核与正式发布确认。
- 当前尚未完成真实模型完整业务、真实 gVisor 部署和生产高可用验收。财经生产使用前需完成实际业务验收；当前状态见 [源码状态说明](REPOSITORY-STATUS.md) 和 [工作模式验证记录](VALIDATION-WORK-MODE.md)。
