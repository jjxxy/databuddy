# 部署后业务验收：办事处月度经营分析

这是可实际上传、核对、复用的验收场景，不是演示脚本。所有企业名、单据、金额和映射均为确定生成的虚构数据。**本包尚未用你部署的真实LLM执行；标准答案生成、文件解析和校验器自测通过，不代表Agent业务验收通过。**

业务用户的任务：把各省收入明细、成本明细和办事处预算合成9月经营分析，生成可核对的Excel与汇报材料；下月复用、更正一张单据、修改成本口径，并能追溯历史版本。入口以对话为主，仍需要上传文件、核对口径和批准有歧义的映射。不要把“能聊天”当成“所有工作都能自动完成”。

多附件、本地目录、Skill/MCP、记忆与上下文压缩追加测试见 [V18-WORKSPACE-ACCEPTANCE.md](V18-WORKSPACE-ACCEPTANCE.md)。

## 先准备

1. 按项目快速启动说明部署，填写你提供的模型配置；选择一个真实可用模型。每个拟开放给业务用户的模型都独立跑本手册。模型更换、版本升级或提示策略调整后重跑核心场景。
2. 创建工作空间“验收_月度经营分析”，关闭其他真实业务资料的接入，避免污染和泄露。记录系统版本、模型显示名称、底层模型版本（由运营者记录）、执行时间、任务ID和下载文件SHA256。密钥不入记录。
3. **首次只上传 `inputs/phase1/` 的两个文件。不要上传 `expected/`、本手册、`fixture_definition.json`、校验器或标准答案。** 测试者看到标准答案；模型只能看到源文件和本手册给出的业务指令。若把答案交给模型，端到端测试无效。
4. 核心场景不依赖互联网登录、OCR或任意Python执行。若Agent必须调用这些能力才能完成，需先验证受控执行器及相应连接已正确配置；未配置时应明确阻断并标为核心用例未通过，不能编造运行结果。

## 文件与业务陷阱

| 文件 | 只在何时上传 | 验证内容 |
|---|---|---|
| `inputs/phase1/2026-09_业务源表.xlsx` | 首次9月 | 四页签、B列/C列起表、两级合并表头、同页两表、元/万元、Excel日期/文本日期、数字/金额文本、比例/百分号文本、负数 |
| `inputs/phase1/业务口径.txt` | 首次9月 | 收入与直接成本定义、粒度、有效期、分母、去重及复用规则 |
| `inputs/phase2/2026-10_业务源表.xlsx` | 月更 | 相同结构的新快照，必须保留9月历史且幂等 |
| `inputs/correction/10月单据更正.csv` | 单据更正 | 按稳定单据ID替换，不新增第二笔收入 |
| `inputs/negative/` | 每个负例单独空间 | 未映射、冲突重复、格式歧义、公式错误，不污染已通过结果 |
| `expected/*.csv`、`expected/gold.json` | 永不上传 | 测试者的独立十进制标准答案 |

收入明细范围为 `收入底稿!B5:I15`，表头5–6行，数据7–15行。第16行控制数包含草稿和跨期，不计入；19–21行另有控制表，不计入。成本为 `成本底稿!C5:I15`，预算 `预算!A4:E7`，映射 `省份映射!A1:D8`。预算E5:E7的毛利公式为同一行预算收入减预算成本，单位万元，用来验证公式知识提取。税率既有数值0.13并设百分比格式，也有文本13%，含义相同；**收入已经是不含税金额，不再做除税计算**。

基准纳入7条收入、7条直接成本；草稿、跨期和研发费排除，退货/退料负数保留。省份明细先汇总到办事处，再对齐预算，避免多对多连接放大金额。先计算再按展示需要四舍五入。“全部”比例由合计分子/合计分母计算，不能平均办事处比例。任何缺失、重复或不明口径都不能用默认0掩盖。

## A01：前台和配置边界

打开业务页面：能看到运营者提供的模型名称并选择；看不到模型密钥、API地址、OpenCode/混合引擎选择、公司发文接入配置。切换模型后发起的新任务使用所选项，正在运行任务的配置不会中途改变。业务凭据不能通过直接请求配置接口读写运营者配置；不能只测按钮隐藏。记录实际HTTP状态及脱敏响应。

若只配置一个模型，单一模型默认可用即可。模型不可用时，界面解释失败和下一步，不得自动声称已完成或悄悄切换为其他来源。这里验证的“业务凭据”应是你的实际部署权限边界；不要把整个实例的管理令牌分发给互不信任的使用者。

## A02–A05：只靠业务指令完成9月

上传phase1文件后，把下文原样发给Agent：

> 我要做2026年9月办事处经营分析。请先读取全部页签和业务口径，识别实际表格范围、表头层级、数据类型、单位和有效映射，不要把控制表或合计行当明细。检查单据ID、费用ID和映射是否重复，明确各字段含义及纳入/排除范围。对混合日期、元/万元、带逗号或¥的金额、括号负数、0.13比例与13%文本，请用可审查的规则归一；不确定之处具体问我，不要猜。用户不需要写代码或修脚本。
>
> 按月份、办事处汇总收入、直接成本、毛利、毛利率，与同月预算比较。收入和成本明细分别汇总后再连接预算，金额使用十进制定点计算，不逐行提前舍入。提取预算毛利列的Excel公式含义，核对公式缓存与预算收入减预算成本一致，再将此规则用于汇总后比较。税率只用于语义检查，不对已经不含税的收入再次除税。“全部”毛利率按全部毛利/全部收入算。转换后有任何未解析行必须明确列出，不得通过转NULL再过滤把异常藏掉。保留来源坐标、源文件版本、筛选和转换规则、处理代码或SQL，方便后续核对与复用。
>
> 先给我口径、异常清单和可核对预览，经确认后生成完整结果。最终结果列名固定为：月份、办事处、收入元、直接成本元、毛利元、毛利率、预算收入元、预算成本元、收入预算差额元、收入达成率、成本预算差额元、收入笔数、成本笔数。每月三家办事处加“全部”合计。比例原子值为小数比例，展示可为百分比，导出保留至少8位小数。请提供完整CSV和Excel下载，不限于页面预览。

若询问表格边界或同义列，按源文件和业务口径确认；若询问0.13/13%，回答“0.13为已存比例，带%文本除以100；仅对明确来源格式作逐类归一”。**合并表头或混合格式被识别后仍无法继续，A02失败；安全阻断虽好，不能替代正确处理正例。** 不允许测试者到后台改数据或手工写脚本帮助通过。

确认后检查（每项独立记录）：

## 运行原子数值校验器

把下载件放到本目录下自行创建的 `results/`，例如 `results/9月结果.csv`。标准表头必须与A02要求一致；比例必须导出原子小数而非“48.04%”文本。多页签Excel使用 `--sheet 结果页签名`。校验器能读标准CSV/XLSX；只用Python标准库，不执行公式、不依赖API或模型。退出0表示数值通过，1表示差异，2表示文件/格式无效。

主机有Python时，从解压后的项目根目录运行：

```bash
python acceptance/finance_monthly/verify_export.py acceptance/finance_monthly/results/9月结果.csv --scenario baseline_sep
python acceptance/finance_monthly/verify_export.py acceptance/finance_monthly/results/10月结果.xlsx --scenario baseline_oct --sheet 结果
python acceptance/finance_monthly/verify_export.py acceptance/finance_monthly/results/两月结果.csv --scenario baseline_both
python acceptance/finance_monthly/verify_export.py acceptance/finance_monthly/results/10月更正.csv --scenario corrected_oct
python acceptance/finance_monthly/verify_export.py acceptance/finance_monthly/results/9月研发口径.csv --scenario include_rd_sep
```

只有Docker时，在项目根目录用只读挂载运行，无需主机安装Python（Linux/macOS）：

```bash
docker run --rm --network none --mount "type=bind,source=$(pwd),target=/check,readonly" -w /check python:3.12-slim python acceptance/finance_monthly/verify_export.py acceptance/finance_monthly/results/9月结果.csv --scenario baseline_sep
```

Windows PowerShell使用：

```powershell
docker run --rm --network none --mount "type=bind,source=$((Get-Location).Path),target=/check,readonly" -w /check python:3.12-slim python acceptance/finance_monthly/verify_export.py acceptance/finance_monthly/results/9月结果.csv --scenario baseline_sep
```

该容器无需网络；首次运行前需已有`python:3.12-slim`镜像。目录路径如含逗号，优先使用项目已经提供的启动环境或Python命令，避免Docker挂载参数歧义。校验器拒绝缺行、多行、重复键、NaN、文本金额、缺缓存公式；金额允许最多0.000001元序列化误差，笔数严格相等，比例允许0.000000005绝对误差。**它不证明来源、权限、审批、复用、报告语义或重启恢复正确；这些仍须逐项实测。**

## 上线判定及未覆盖范围

在 `验收记录模板.csv` 逐项记录状态、任务ID、实际产物、校验JSON、人工复核和失败原因。核心A01–A11及N01–N07必须全部通过；有一分钱错误、错误期间/口径、重复累计、来源缺失、密钥泄露或未正确披露过期结果，都不能算本场景可上线。至少对拟开放的每个模型完整跑一次，并重复正常重跑/月更/更正，不用“平均正确率”掩盖关键错数。

本场景只覆盖一条完整月结业务链。它未证明：任意企业模板都能正确理解、百万行性能、OCR准确率、所有网站登录/iframe导出、远程代码执行沙箱、真实Excel计算引擎、多租户隔离、所有Office输入格式、共享协作权限、备份恢复演练及并发容量。按实际业务另补样本和容量/安全测试；不能用这里的几十条虚构数据外推任意规模或100%准确。来源网站和公司的认证/访问权限也需要运营者单独配置；仅提供LLM不会自动获得它们。
