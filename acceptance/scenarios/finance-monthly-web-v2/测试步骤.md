# 测试步骤

本案例使用虚构数据。业务模拟网站仅监听本机回环地址，目的是提供可重复的网页、下载和接口数据，并不是互联网上真实的业务平台。

1. 解压测试包，打开 `web` 目录，双击 `start.cmd`。它先查找包内的 Python，再尝试使用同工作区 Atlas 便携包自带的 Python。若提示未找到运行时，需要测试环境提供 Python 3；不能声称该测试包在没有运行时的机器上一定可启动。不要关闭启动窗口。
2. 在**运行模拟网站的同一台电脑**用浏览器打开 `http://127.0.0.1:8765/`，检查主页、订单翻页、三个附件下载和退款接口。若 8765 已被占用，先处理端口冲突；不要终止不明进程。
3. 在 Atlas 工作区上传 `inputs` 内的两份复杂 Excel，复制 `需求描述.md` 的业务需求提交。`answer` 目录是测试者的标准答案，不应上传给系统。
4. 分别测试：让系统读取订单多页网页；让系统读取退款分页 API；让系统下载并读取总账附件。记录每一步能否访问、是否遍历全部分页和文件、是否保留来源。订单网页与订单下载文件是同一数据，不能重复相加。
5. **本地地址限制**：Atlas 的 API 连接器默认禁止访问 `localhost` / `127.0.0.1`。仅在隔离的本机测试环境中，管理员可在项目服务的启动配置中显式设置 `API_ALLOWED_HOSTS=127.0.0.1` 并重启该测试服务；这不是要求修改生产网络策略。云端浏览器或其他电脑上的 `127.0.0.1` 指向其自身，默认不会到达你电脑上的模拟网站。必须由管理员提供经授权的可达测试部署，才可测试云端自动访问。
6. 如果受网络或项目能力限制，系统无法访问网页或接口，请如实记录该项失败或未验证。可在用户浏览器下载模拟网站上的订单、退款、总账文件，再手动上传以继续测试财务加工；手动上传不算自动网页访问、自动下载或接口分页通过。
7. 系统完成后，人工对照 `answer` 中的标准答案和检查说明，重点核查跨期退款、重复及冲突记录、正式预算与单位、账实差异、来源行号以及报告和 PPT 的一致性。遇到差异，应要求系统解释来源和处理过程，不要仅看最终合计。

可选异常测试：接口 URL 追加 `&simulate=rate_limit` 可触发首次请求 429 与 `Retry-After`；第二次请求同一 URL 应恢复。观察系统是否如实报告限流并合理重试，不把这个可选测试混入基本账务结果。
