# 测试步骤

本案例的全部数据为虚构材料。请先将压缩包完整解压，再操作，不要把包含标准答案的整个 ZIP 直接上传给系统。

1. 打开 `web` 文件夹，双击 `start.cmd`。它会尝试使用同工作区 Atlas 便携包自带的 Python；若找不到运行时，请参照提示使用已有 Python 3 运行 `server.py`。本模拟网站只监听本机，关闭启动窗口即可停止。
2. 在运行网站的电脑浏览器打开 `http://127.0.0.1:8765/`，查看订单分页、附件下载和退款接口。
3. 在 Atlas 新建工作项目，只上传 `inputs` 内的资料，复制 `需求描述.md` 的正文发给系统。`answer` 是给测试者核对的答案，务必不要上传。
4. 按网页、下载、API 分页和跨文件核算分别记录真实结果。要求系统先列取数计划，明确访问失败和资料不全；完成后检查 Excel、报告和 PPT 是否一致，关键数字能否追溯。
5. 完成后再阅读 `answer`。检查正式口径与历史草稿、PPT 目标与实际、重复单据、退款跨期、预算单位、账实差异、图片识别和未确认线索是否被正确区分。

## 本机地址限制

Atlas 的 API 连接器默认禁止访问 `localhost` 或 `127.0.0.1`。仅在隔离的本机测试环境中，管理员可在项目服务启动配置中明确设置 `API_ALLOWED_HOSTS=127.0.0.1` 并重启该测试服务；不要因此更改生产网络策略。云端服务和云端浏览器中的 `127.0.0.1` 指向云端容器自身，默认无法到达你电脑上的模拟网站；管理员需要提供经授权、从部署环境可达的测试网站。

如果网页或接口无法自动访问，应记录失败或未验证；可由用户浏览器下载模拟数据，再手动上传以继续测试数据处理。人工下载并不等于系统自动爬取、自动下载或接口分页通过。

接口 URL 加上 `&simulate=rate_limit` 可在首次请求时返回 429 和 `Retry-After`，第二次请求同一 URL 恢复，用于单独测试异常处理。复核图像中的金额时须对照原图，识别出的文字不能自动视为财务已确认。

`11_财务正式口径通知.docx` 与同名 TXT 的正文一致，作为同一份通知交叉检查，不是两份独立审批。Word 样本仅验证可读取正文，未验证排版。
