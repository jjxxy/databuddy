# 财务结果的来源与核对

Atlas 面向财经及经营分析，结果能解释、能回查，是让人开展复核的基础；它不能单独证明原始资料完整、会计口径正确或获得财务审批。流程图、文件摘要、模型回答和规则通过都不应作为财务正确性的替代证明。

## 在报告里查看依据

在项目成果中打开由完整数据结果生成的业务简报，展开“这份报告怎么得到的”。页面根据报告及运行时保存的记录，分开说明来源版本和表格选择、当次加工步骤与行数、指标值和计算方式、已配置检查以及仍需核对的事项。点击“查看当次来源”时同时核对项目、来源版本和文件摘要；原件不可用或版本不符时，不会自动替换为最新版本。可以回看记录齐全且仍可用的当次加工结果；来源、规则或结果缺失时明确提示。

说明读取的是当次冻结的加工方案和执行回执，不从后来修改的草稿或模型推测当次过程。已采用结果可能来自复用方案的自动刷新，不能据此推断每次都经人工逐项复核。规则未配置、检查证据不足和财务口径未复核时须分别标明；从报告或数据表的一行准确反查到全部原文件单元格，以及对任意 Office 文件自动建立完整依据，目前仍未实现。

## 精确校验与历史结果

数值范围和合计对账使用定点十进制；超出 JavaScript 安全整数范围的阈值、所有有小数的阈值应使用固定十进制字符串（如 `"0.13"`），不能用浮点数或科学计数法冒充精确值。已是浮点的列或无法证明视图转换精度的数据需要回到原始资料重新处理；数值校验只是对所接收值及所配置规则的检查，不能恢复更早已经丢失的精度，也不能证明规则或来源业务正确。

旧版范围检查曾把值转为浮点比较，历史结果如果有范围或总额检查且缺少新的精确检查回执，仍可作为历史成果只读查看，但不得再次采用、用于新简报或作为新加工的上游输入；请从原始资料重新运行并复核。历史 SQL 如果曾经通过浮点除法等运算造成精度损失，即使结果已经转回十进制，也不能恢复原始值；新报告、再次采用和下游加工会检查冻结的方案与完整上游结果链，发现不安全运算或证据缺失时要求从原始资料重算。旧版加工方案中的不安全除法同样不能重新发布或回滚。历史报告仍可只读查看，并提示需要核对。已有正式成果不会自动删除、改写或重新发布。

## 对照成熟产品

- [Tableau Data Guide](https://help.tableau.com/current/pro/desktop/en-us/data_guide.htm) 把数据来源、筛选和上下文放在用户正在查看的内容旁边；[Explain Data](https://help.tableau.com/current/pro/desktop/en-us/explain_data_explained.htm) 明确统计解释不能证明因果。借鉴按内容展开、明确边界，不把模型的解释当作数值证据。
- [Power BI 下钻](https://learn.microsoft.com/en-us/power-bi/guidance/report-drillthrough) 支持从汇总进入带筛选上下文的明细；[数据血缘](https://learn.microsoft.com/en-us/power-bi/collaborate-share/service-data-lineage)展示来源、模型和报表的关系，访问受权限及连接覆盖限制。借鉴固定版本的回查和权限检查。
- 开源 [OpenLineage](https://openlineage.io/docs/spec/object-model/) 提供运行、数据集与步骤依赖的元数据模型；它需要真实执行器采集，不能根据一张图补造未记录的血缘。[Marquez 入门部署](https://openlineage.io/getting-started/)还需要额外服务。本轮沿用现有运行回执，不增加后台服务。
- 开源 [Great Expectations](https://docs.greatexpectations.io/docs/core/define_expectations/) 将规则组织成可执行的检查，规则、覆盖范围和结果仍需要人维护。本项目已有数据契约，先修复其精度并显示实际执行的规则，不为本轮引入额外依赖。

## 尚需完成的验收

完整真实模型财经月结 A02–A05 尚未通过独立标准答案验收；真实脱敏业务样本、规则长期复用、Excel 公式重算、报表与 PPT 实际渲染、百万行和并发容量、多租户权限与云端部署也尚未完成相应业务验收。优先收集并核对用户实际口径和例外，再用可审计数据分层验证；仅合成样例、界面截图或单元测试不能替代这些验收。
