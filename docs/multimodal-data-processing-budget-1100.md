# 财经多模态数据处理需求特性与工作量预算

**用途：** 多模态数据处理专项的立项及预算申请。

**目标：** 面向财经和经营分析资料，处理表格、文档和图片，形成可核对、可追溯的数据结果。

**工作量目标：1,100 人天。** 以下按指定预算目标对需求进行初步分配，并非独立测算得出的精确报价；应在样本、数量和验收标准明确后重新核算。本专项与原项目整体预算存在范围交叉，两份人天不能直接相加。

## 测算范围与假设

- 清单仅覆盖多模态数据接入、解析、处理、核对、溯源、数据交付和专项验收；通用工作台、企业身份、权限体系及通用运维不计入本清单。
- 默认场景包括财务表格、报表、发票或合同资料的文本、图表及扫描图片。
- 格式以约定的 XLSX、CSV、PDF、PNG、JPEG 为基础；文件体量、页数、文字语言、数据质量、模板数量与并发目标须在实施前约定。
- 图表数字以原始数据或人工核对为准；对 OCR 和图像识别中的低置信度结果或无法识别部分应提示人工复核，不承诺全自动百分之百准确。
- 工时按 1 人 1 工作日 8 小时计，各条包括需求细化、设计、开发和单项测试；跨模态样本标注、专项验收与用户试用集中列于最后一类，避免重复计量。
- 模型和 OCR 采用经选型和授权的服务或组件；模型调用、云计算与存储、第三方许可、购买数据、外部系统改造、税费和长期运维费用不包含在人天中。
- 需业务方提供经授权的样本与真实口径，并指定人员参与抽样标注、关键字段核验及验收；敏感信息处理规则和可使用的模型服务须另行确认。

## 特性与人天分配

### 一、多模态资料接入（100 人天）

多格式资料接收：用户可上传约定范围内的表格、文档和图片资料。

文件类型识别：系统识别资料格式并对不支持或无法读取的文件给出明确提示。

批量资料组织：用户可将同一业务任务的多个文件组织为一批待处理资料。

原件版本记录：系统记录每份资料的文件版本与完整性信息，支持之后核对原件。

输入条件检查：系统检查文件大小、损坏、密码和编码等输入条件并提示处理方式。

资料范围确认：用户可确认本次处理使用的文件及其业务期间。


### 二、表格与结构化数据解析（160 人天）

工作簿读取：系统按用户选择读取 Excel 工作簿中的指定页签与数据区域。

复杂表头解析：系统识别多层表头和合并单元格并呈现待确认的字段关系。

表格结构核对：用户可核对隐藏行、合计行与空白区域的处理范围。

文本与数字区分：系统保留编号、日期、金额和文本等原始表示以供核对。

公式与缓存值提示：系统标识公式及其可读缓存值，并在未重新计算时明确提示用户。

CSV 规范解析：系统识别约定编码和分隔方式并提示无法确定的解析条件。


### 三、文档、图片与扫描件识别（170 人天）

文档文本提取：系统从约定类型的电子文档和可检索 PDF 提取正文及表格内容。

页面与图像预处理：系统对旋转、倾斜或模糊的扫描页面进行适当处理并保留原始图像。

扫描文字识别：系统识别约定语言的扫描件文字并标出无法可靠识别的片段。

版面结构识别：系统区分页面标题、段落、表格与附注并保留页面位置。

财经字段提取：系统从约定的发票、合同或报表样本中提取金额、日期和业务主体等字段。

扫描表格还原：系统识别扫描表格的行列及单元格内容并供用户与原件逐项核对。


### 四、图表数据识别（90 人天）

图表位置识别：系统定位文档或图片中需要处理的图表区域。

图表文字提取：系统提取图表标题、坐标轴、图例及可见数据标签。

图表单位提示：系统提示图表中的单位、刻度和期间需要用户确认。

可见数值整理：系统整理图表中清晰可见的数据标签，并标记无法准确读取的数值。

图表原件回看：用户可对照原图核对图表数据并确认是否使用。


### 五、跨模态关联与语义对齐（100 人天）

跨文件字段对齐：系统按照用户确认的字段含义关联表格、文档或图片中的同类信息。

业务主体匹配：系统基于明确的标识匹配合同、单据和表格中的业务主体。

期间与版本对齐：系统提示跨资料期间或版本不一致，并让用户确认适用范围。

不确定匹配处理：系统对多个候选、缺少标识或可能混淆的记录提示人工确认。

跨来源冲突比较：用户可查看不同资料对同一字段的冲突并选择可采用的依据。


### 六、财经精度与数据加工（150 人天）

金额与单位解析：系统按照确认的元、万元及负数表示规则转换不同资料中的金额。

百分比口径解析：系统区分小数比例与百分号文本并在含义不明时要求确认。

日期与会计期间：系统按确认规则处理不同日期格式及会计期间。

财务口径冲突提示：系统提示含税、币种、汇率、预算版本及当期累计口径的冲突。

精确计算与舍入：系统按约定的十进制精度和舍入规则计算财务结果。

表格数据关联：系统按确认的关联键合并数据并检查重复关联导致的金额放大。


### 七、质量检查与人工复核（115 人天）

必填与完整性检查：系统检查约定的必填字段、缺失内容和资料覆盖范围。

金额对账：系统按确认规则核对单据、明细和合计金额并展示差异。

重复与异常检查：系统识别约定范围内的重复资料、重复记录和异常值。

识别结果人工校正：用户可对照原文或原图修正识别错误并保留修正记录。

高风险结果阻断：当关键金额、口径或识别证据不满足约定条件时系统阻止结果作为正式数据使用。


### 八、过程说明与数据溯源（105 人天）

来源与版本说明：用户可查看结果使用的资料名称、版本和处理范围。

原文原图定位：用户可从提取结果回看有记录的原文、页码或图片区域。

数据处理过程说明：用户可用业务语言查看资料如何识别、对齐、筛选和计算。

检查结果说明：用户可查看实际执行的检查、结果和仍需人工确认的事项。

复核与修订留痕：系统记录关键数据的人工确认、修改及对应资料版本。


### 九、数据输出与专项验收（110 人天）

结构化结果导出：用户可将确认后的多模态处理结果导出为约定的表格数据。

依据清单导出：用户可导出结果对应的来源、处理范围和检查记录。

脱敏样本与标准答案：项目组基于授权样本建立覆盖约定模态的脱敏测试集和标准答案。

识别准确性评估：项目组按约定字段、样本和指标评估识别结果并记录错误案例。

财经业务验收：财经用户按约定场景核对原件、识别结果、计算数据与异常提示。


**合计：1,100 人天。**

## 预算与验收边界

1. 人天是按 1,100 人天目标分配的专项规划；以人天单价换算金额时，还应另列模型服务、算力、存储及第三方许可等费用。
2. 在立项前明确样本数量、表单模板、页面质量、文字语言、单文件及总数据规模、并发目标和人工复核责任，否则无法据此判断实际投入或交付工期。
3. 识别准确率、字段级错误率和不可识别样本处理方式应在标准答案确认后按不同模态和字段分别约定，不能仅使用整体平均准确率代表金额等关键字段的可靠性。
4. 来源真实性、业务口径和人工复核由相应业务负责人确认；系统展示的完整性和检查记录不能替代财务审批。
