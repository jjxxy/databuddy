# Atlas DataBuddy 财经智能工作空间需求特性与工作量预算（初稿）

**用途：** 项目立项及预算申请讨论。

**目标：** 建设面向财经和经营分析用户的工作空间，让用户通过浏览器提出需求，完成数据接入、核对、加工、报告生成与业务复核，并能看懂每份成果的依据。

**工作量目标：1,100 人天。** 以下为按提出的 1,100 人天预算目标分配的初步规划，不是独立测算得到的精确报价；实际需求、集成范围和样本确认后须重新评估。

## 估算口径

- 本表估算的是在现有项目基础上继续完善、集成、测试与交付的计划工作，不把历史已投入人天计入，也不按从零重做产品估算。
- 1 人天按 1 名项目成员 8 小时计，包括相应特性的需求细化、设计、开发及该特性的基本测试；跨场景业务验收、上线演练和培训统一列在最后一类，避免重复计量。
- 范围假设为一个财经工作空间产品，接入数量有限且接口由对方提供并授权，优先 Excel/CSV 和已约定的数据源；模型服务、服务器及企业身份系统由实施方另行选定并提供。
- 工作量不包含云资源、模型调用、第三方软件许可、采购税费、长期运维人员、企业底稿整理及外部系统改造费用；按各方日费率另行换算预算金额。
- 项目范围、数据规模、对接系统数量、权限模型、报告母版复杂度及专业合规要求会影响投入，1,100 人天应在明确上述条件后复核，不能视作保证值。

## 立项和验收注意事项

1. 数据来源的真实性、完整性及业务口径需要业务负责人确认；系统计算和检查通过不自动等同于财务结论正确或已审批。
2. 来源取证应保留权限和历史版本；如需所有指标逐单元格回溯、扫描件 OCR、特殊 Excel 格式、复杂母版、更多外部系统或高可用指标，须另行明确范围并重新评估预算。
3. 在启动前确认接入对象、数据规模、验收样本、口径责任人、系统边界及人天单价；外部依赖和业务确认等待时间应纳入计划工期，但不能直接换算成开发人天。
