# 面向真实财经工作的验收方向

本文件是面向产品和验收的工作清单，不等于这些能力已经全部实现。合成样例通过不代表真实企业数据、组织权限或生产容量已通过。

## 优先验证的工作

1. **月结与经营汇报**：导入收入、成本、预算和组织映射，识别期间、单位、含税口径与版本；对账后生成明细、报告和汇报材料，并能解释每个数字的来源。
2. **差异排查和更正**：发生缺失、重复、跨期、汇率不一致或数据更正时，定位原始行和规则；不凭相似字段猜测口径，不覆盖已确认结果。
3. **月度复用**：复用已确认的流程、规则和模板处理新月份，记录新旧输入和执行版本，允许查看上期差异。
4. **经营分析的多来源取数**：明确区分完整导入、数据库查询和 API 分页；能证明取数范围、新鲜度、分页结束和失败时哪些数据尚未取得。
5. **报告及汇报交付**：保留数值精度和单位，说明来源及核对状态；按用户上传的模板生成时，不能把不支持的模板对象或未知视觉结果称为保真。
6. **流程调试与恢复**：支持按版本核验节点输入输出、选择可安全调试的步骤；自动检查失败应阻断，只有明确要求人工复核才暂停；修复要保存原因、变更和新结果。
7. **团队使用**：按用户和项目限制源数据与成果权限，保留访问、修改和执行记录；验证并发、备份恢复和误操作恢复。

## 商业产品中可借鉴的特征

- [Power BI 数据沿袭](https://learn.microsoft.com/power-bi/collaborate-share/service-data-lineage)将来源、处理和成果的依赖放在同一视图，并展示刷新信息；本项目应同时让业务用户看到本次执行的来源版本和结果，而不只是一张静态流程图。
- [Power BI 刷新机制](https://learn.microsoft.com/power-bi/connect-data/refresh-data)区分不同数据模式及刷新范围；本项目应区分实时查询与固定快照，避免把当前样本冒充历史结果或完整来源。
- [Tableau 数据资产权限](https://help.tableau.com/current/server/en-us/dm_perms_assets.htm)将沿袭和质量信息纳入权限控制；本项目的过程、输入、异常和结果查看也必须遵守项目及用户授权。
- [OneStream Financial Close 指南](https://documentation.onestream.com/9.2.0/Content/PDFs/OFC/OFC_PV9.0.0_SV100_Instructions.pdf)包含对账与审计记录；本项目应记录明确的对账依据、差异及复核结论，而不是把图表精美或任务成功等同于财务正确。

## 完成标准

每条能力应具备真实可执行路径、权限和版本边界、明确的失败提示及独立验收数据。财经月结核心场景以 `acceptance/finance_monthly/` 中的标准答案和校验器为起点；尚未进行真实模型端到端验证的项目必须继续标记为未验证。大规模、并发、跨系统、复杂模板、实际企业样本和灾备需分别验证。
